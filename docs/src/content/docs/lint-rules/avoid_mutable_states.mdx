Avoid mutable fields and setters on `Bloc` and `Cubit` states.

## Rationale

State is exposed to the UI via the `state` getter and compared between
emissions to determine whether listeners should rebuild or react. If a state
is mutated in place after being emitted, previously captured references
observe the same, now-changed, data and comparisons against prior states can
no longer be trusted.

Mutable fields also break value equality, which blocs, cubits, and widgets
such as `BlocBuilder` rely on when deciding whether to rebuild — for example
when extending `Equatable`.

Modeling states as immutable value objects keeps every emission a faithful,
independent snapshot.
